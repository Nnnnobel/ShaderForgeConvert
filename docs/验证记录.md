# 验证记录

基线：2026-09-20；Unity 2022.3.62f3，macOS，Built-in Render Pipeline；Shader Forge 上游提交 `3bde185e67178b687b4d0b1964367355aef471f8`。这些记录证明包可安装、转换器可处理样本、导出的 Shader 在此编辑器环境中可导入，并对一份示例完成初步像素对照；尚未证明一般场景、材质与平台等价。

## 公开包安装

在全新 Unity 工程的 `Packages/manifest.json` 中加入：

```json
"com.shaderforgeconvert": "https://github.com/Nnnnobel/ShaderForgeConvert.git?path=/Packages/com.shaderforgeconvert"
```

Unity Package Manager 将包解析为 Git 依赖，产生 `packages-lock.json`，编辑器脚本编译完成。首次安装时，本机 Command Line Tools 的 x86_64 `xcrun` 与仅含 arm64/arm64e 的 `libxcrun.dylib` 不匹配；临时把 Git 命令转为 arm64 运行后安装成功。这个问题属于本机工具链，不是包的编译错误。

## 样本导入

使用上游的 10 个 Shader 预设和 10 个示例。每份先导入原文件，再调用 `ShaderConverter.Convert`，写入新名称的 `.shader` 并调用 `ShaderUtil.ShaderHasError` 检查导出文件。

| 样本组 | 数量 | 图解析与转换 | 原文件导入错误 | 导出文件导入错误 |
| --- | ---: | ---: | ---: | ---: |
| Shader Presets | 10 | 10/10 | 0 | 0 |
| Example Assets/Shaders | 10 | 10/10 | 0 | 0 |

20 份输出仍全部标记为 `Partial`。成功导入只覆盖当前编辑器检查的 Shader 编译状态，不代表所有关键词变体、图形 API、平台或画面一致。

对同一批 20 份原/导出 Shader，另比较了属性数量、名称、类型、材质默认值、纹理默认值与缩放偏移、渲染队列、Pass 数量与名称、常见 SubShader 标签；探针报告 `contractFailures=0`。这项检查覆盖列出的公开材质契约，不涵盖每个 Pass 内部的渲染状态和所有关键词变体。

本轮修正了统计口径：只有 HLSL/CG 代码区中真正被替换的标识符才计入“已重命名”。例如 `VertexAnimation` 的图注释给出 3 个候选名称，但输出源码实际只替换 1 个；另 2 个节点的生成代码没有以对应 `node_ID` 变量出现。该统计不等于已重构的节点数。

## 初步像素对照

在同一台 Mac 的 Metal 后端，用 [`PixelProbe.cs`](../tools/UnityBatchProbe/PixelProbe.cs) 对上游 `VertexAnimation.shader` 和导出 Shader 渲染 128×128 图片。两者使用相同的 8×8 测试纹理、球体、相机和定向光，分别取 `_BulgeScale=0.1` 与 `0.4`；两次对照均为 `changed=0`、`maxDelta=0`。原图非黑像素分别为 3455 和 5863，说明这两个参数配置产生了不同的可见形状。

该样本的生成代码包含 `metal` 渲染器。上游 `PresetUnlit` 和 `PresetParticleAdditive` 的 `#pragma only_renderers` 不包含 Metal；后者在本机报告 `isSupported=False`，因此没有把它们的 Metal 截图当作效果验证。像素结果只适用于这份样本、这两组参数及当前设备；仍需用户真实材质和目标平台的对照。

## 核心规则测试

`dotnet run --project tools/SmokeTests/SmokeTests.csproj` 覆盖 SF_DATA 图读取与可达节点、节点备注重命名、注释保留、元数据及专用 Inspector 移除、损坏图和重名拒绝。本轮增加宏续行保护、已有名称碰撞与“仅在注释中出现的标识符不得计入已重命名”测试。

## 复测方法

1. 建一个不含 Shader Forge 编辑器的 Unity 2022.3 临时工程，用上面的 Git URL 安装包。
2. 从固定上游提交复制 10 个预设和 10 个示例 `.shader` 到 `Assets/Samples`。上游文件仅用作本地测试，不随本项目分发。
3. 将 [`tools/UnityBatchProbe/ConversionBatchProbe.cs`](../tools/UnityBatchProbe/ConversionBatchProbe.cs) 复制到临时工程的 `Assets/Editor`。
4. 用 Unity Batchmode 的 `-executeMethod ConversionBatchProbe.Run` 运行，检查日志中的 `BATCH_PROBE` 与 `BATCH_SUMMARY`。若发生转换异常、相对原文件新增的 Shader 导入错误或材质契约差异，探针会失败。
5. 若设备支持 `VertexAnimation` 的目标渲染器，将 [`PixelProbe.cs`](../tools/UnityBatchProbe/PixelProbe.cs) 也复制到 `Assets/Editor`，在**不加 `-nographics`** 的 Batchmode 中运行 `-executeMethod PixelProbe.Run`。该探针要求上一步已生成 `Assets/Converted/VertexAnimation.shader`，并在图像未实际绘制或像素差值超过 1 时失败。
