# 可行性与转换边界

调研基线：2026-09-20， [FreyaHolmer/ShaderForge](https://github.com/FreyaHolmer/ShaderForge) 提交 `3bde185e67178b687b4d0b1964367355aef471f8`。这里的“保留实现”指在指定 Unity 版本、渲染管线与测试条件下，属性、渲染状态及画面与原 Shader 一致；源码相似或编译成功不足以证明这一点。

## 为什么能做

Shader Forge 将节点图作为 `/*SF_DATA;...*/` 写在生成的 ShaderLab 前面。节点类型、ID、连接、属性名和备注保留了计算意图；后面的 ShaderLab/CG 代码则记录了实际的 Pass、宏、光照与渲染状态。[图序列化](https://github.com/FreyaHolmer/ShaderForge/blob/master/Shader%20Forge/Assets/ShaderForge/Editor/Code/SF_EditorNodeView.cs#L728-L754)、[保存流程](https://github.com/FreyaHolmer/ShaderForge/blob/master/Shader%20Forge/Assets/ShaderForge/Editor/Code/_Evaluator/SF_Evaluator.cs#L3315-L3339)

转换器同时读取这两部分：沿 Final 输入反向找到参与输出的节点，在已有代码中定位对应变量与表达式，再逐步整理命名和函数。原 ShaderLab 是行为基线。单靠图重新生成整套光照与 Pass，会引入大量等价风险；单靠格式化生成文本，则无法恢复节点意图。

Shader Forge 自身的 [SF_Parser](https://github.com/FreyaHolmer/ShaderForge/blob/master/Shader%20Forge/Assets/ShaderForge/Editor/Code/SF_Parser.cs#L47-L115) 还有分隔符转义和 SubShader 的 TODO，历史图数据不能视为完全一致的格式。没有连接 Final 输出的图无法追踪效果链，当前版本会拒绝转换。

## 一个具体问题

上游 [VertexAnimation.shader](https://github.com/FreyaHolmer/ShaderForge/blob/master/Shader%20Forge/Assets/ShaderForge/Example%20Assets/Shaders/VertexAnimation.shader) 中，Panner、Frac、Subtract、Abs、Multiply 与 Power 构成渐变链；结果参与顶点偏移、漫反射和自发光。生成代码把相关计算分布到顶点与片元程序中。同一表达式跨阶段出现，也不能直接合并为一次计算：插值位置、精度和光照路径会随之改变。

可安全重构的单位必须限定在同一 Pass、同一阶段和相同宏条件下。函数提取前需确认参数、类型、作用域、求值次数及采样位置。属性、Blend、ZWrite、Cull、关键词、阴影和 Fallback 仍按原实现保留。[生成器](https://github.com/FreyaHolmer/ShaderForge/blob/master/Shader%20Forge/Assets/ShaderForge/Editor/Code/_Evaluator/SF_Evaluator.cs#L3029-L3042)

## 实现范围

当前包从 `SF_DATA` 读取节点/连线并追踪 Final 依赖；在 CG/HLSL 程序区中重命名可映射的变量，对严格的单一 Emission 声明序列提取函数。无法识别的表达式保留原代码，输出状态始终是 `Partial`。清理 `SF_DATA` 和专用 `CustomEditor` 只是导出步骤，不能单独算作逻辑转换。ShaderImporter 的默认纹理还需要逐例核对。[默认纹理写入](https://github.com/FreyaHolmer/ShaderForge/blob/master/Shader%20Forge/Assets/ShaderForge/Editor/Code/_Evaluator/SF_Evaluator.cs#L3342-L3390)

目前优先处理 Built-in 管线的 Unlit 和简单效果：属性、常量、基础算术、UV、纹理、颜色与顶点偏移。PBR/GI、Deferred、ForwardAdd、ShadowCaster、Meta、曲面细分、GrabPass、实例化与自定义代码需按 Pass 和节点逐项验证。URP/HDRP 涉及管线迁移，不属于当前转换范围。[Unity 渲染管线功能比较](https://docs.unity3d.com/6000.0/Documentation/Manual/render-pipelines-feature-comparison.html)

[ShaderCleanup](https://github.com/Agentlien/ShaderCleanup) 针对 Shader Graph 已生成代码做顺序清理，证明后处理有可用场景，但它的匹配规则与 Shader Forge 的图格式和生成器不通用。本项目借鉴规则独立执行与逐项验证的做法，具体实现见[架构调研](./Shader%20Forge%20与%20Shader%20Graph%20架构调研.md)。

## 完成标准

一份完成转换的 Shader 应能从输入属性、节点运算追到 Final 输出；主要效果链成为可理解的变量和函数，报告标明节点与源代码的对应关系。Unity 导入检查、属性与 Pass 契约、固定场景的图像对照都要通过，范围以实际验证的版本与渲染器为准。

当前 [20 份上游样本的导入与契约检查](./验证记录.md)通过，`VertexAnimation` 的两组 Metal 画面逐像素一致。这些结果只覆盖各自的测试条件，尚不能给整个节点库或一般项目输出 `Full`。
